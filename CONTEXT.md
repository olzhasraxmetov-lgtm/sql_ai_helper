# Словарь проекта

Общие термины для кода, промптов, тестов и обсуждений. Правила подсчёта метрик — в `docs/sql-rules.md`.

| Термин | Значение |
|---|---|
| **Вопрос** | Запрос владельца магазина на естественном языке, например «какой жанр был популярен за сезон?». |
| **Уточнение** | Встречный вопрос системы, когда вопрос неоднозначен. Система не угадывает молча и не выдаёт ответ, пока неоднозначность не снята. |
| **Термин, требующий уточнения** | Слово или фраза из списка в `docs/sql-rules.md`, при которых уточнение обязательно, например «лучше продавались», «сезон». LLM может запросить уточнение и сверх списка. |
| **Журнал вопросов** | Записи сервиса о каждом вопросе: вопрос, уточнения, сгенерированный SQL, итог, стоимость, отзыв. Хранится в схеме `app`, недоступной LLM. |
| **Итог** | Что сервис сделал с вопросом. Записывается автоматически: `answered`, `clarification`, `rejected` (не прошёл проверку SQL), `execution_error`, `timeout`. Ничего не говорит о том, верен ли ответ по смыслу. |
| **Отзыв** | Оценка владельца 👍/👎 с необязательным комментарием, привязанная к записи журнала. Источник кандидатов в тестовый набор. |
| **Тестовый набор** | Вопросы с эталонным SQL, проверенным `sql-reviewer`, и ожидаемым ответом либо пометкой «модель должна запросить уточнение». Единственная мера точности модели. |
| **Фоновые данные** | Данные генератора (Faker, фиксированный seed) за фиксированный период 2024-11-01 — 2026-10-31: сезонность, хиты, повторные покупатели. |
| **Подсаженный случай** | Явно заданная строка поверх фоновых данных, проверяющая конкретную ловушку (например, платёж в 23:50 31 марта). Лежит в периоде, о котором спрашивает тестовый набор. |
| **Сегодня** | Текущая дата по `Asia/Almaty`, которую получает цепочка через `Clock`. Может быть зафиксирована настройкой `APP_TODAY` (демо) и всегда зафиксирована в тестах. |
| **Прошлый месяц** | Предыдущий календарный месяц по `Asia/Almaty` относительно текущей даты. Это правило, уточнения не требует: 3 октября «прошлый месяц» — сентябрь. |
