## Проект

Text-to-SQL по базе интернет-магазина книг (PostgreSQL): владелец задаёт вопрос обычным
языком, LLM пишет SQL, сервис безопасно выполняет его и объясняет результат. Портфолио-проект.

- Контекст, план и решения: `docs/bookstore_text2sql_context.md`
- Схема БД: `db/bookstore_schema.sql`
- Правила предметной области (смысл колонок, статусы, как считать выручку): `docs/sql-rules.md` —
  единственный источник; промпт LLM, тестовый набор и ревьюер читают правила оттуда.

## Стек

Веб-сервис на FastAPI (не Telegram-бот).

- Python 3.12, FastAPI, pydantic / pydantic-settings
- PostgreSQL 16; миграции — Alembic
- Выполнение сгенерированного SQL — отдельная read-only роль PostgreSQL, `statement_timeout`, лимит строк
- Разбор и проверка SQL перед выполнением — sqlglot
- Тесты — pytest; линтер и форматтер — ruff; типы — mypy (strict); зависимости — uv
- Запуск — Docker Compose (сервис + PostgreSQL)
- Архитектура — чистая, слои `domain` → `application` → `infrastructure` / `presentation`, как в предыдущем проекте

Ещё не решено (обсуждается в brainstorm): провайдер LLM, способ доступа к БД из приложения
(SQLAlchemy async или asyncpg напрямую), интерфейс для пользователя (веб-страница или Telegram-бот поверх API).

## Проверка SQL

Любой эталонный запрос или запрос в тестовом наборе перед тем, как считать его правильным,
проверяй субагентом `sql-reviewer`. Передавай ему только вопрос и SQL — без своих рассуждений
о том, как запрос писался, иначе ревью перестаёт быть независимым.

## Когда меняется схема или бизнес-логика

1. Изменение схемы — только через миграцию.
2. Обновить `db/bookstore_schema.sql` выгрузкой из базы (`pg_dump --schema-only`), а не руками.
3. Если поменялся смысл данных (новый статус, новое правило подсчёта, новая метрика) —
   обновить `docs/sql-rules.md`.
4. Добавить 1–2 эталонных вопроса на изменение в тестовый набор и проверить их `sql-reviewer`.

## Как работать с автором

Автор учится и предпочитает разбираться сам: объясняй ошибки и задавай наводящие вопросы,
давай конкретные примеры с данными, а не абстракции. Готовое решение — только по прямой просьбе.
