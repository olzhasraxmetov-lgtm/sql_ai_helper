# 0003. Доступ к БД — asyncpg напрямую, SQLAlchemy только для Alembic

**Статус:** принято, 2026-10-20

## Контекст
Основной SQL сервиса пишет LLM: произвольный текст, заранее неизвестный. Его нужно выполнить
под read-only ролью с таймаутом и вернуть строки вместе с именами колонок. Кроме того,
генератор данных заливает большие объёмы, а сервис ведёт журнал вопросов (свои таблицы).

## Решение
- Сервис и генератор данных работают через asyncpg без ORM.
- SQL от LLM выполняется в транзакции `readonly=True` под отдельной ролью, `statement_timeout`
  задаётся через `server_settings` подключения.
- Генератор данных пишет через `copy_records_to_table`.
- SQLAlchemy остаётся только как зависимость Alembic для миграций.

## Последствия
- Запросы журнала пишутся вручную, без ORM; моделей таблиц в коде нет.
- Если таблиц приложения станет много, решение стоит пересмотреть в пользу SQLAlchemy Core.
