# 0001. Неоднозначные вопросы уточняются, сервис без состояния

**Статус:** принято, 2026-10-20

## Контекст
Вопросы владельца часто допускают несколько прочтений: «лучше продавались» — по экземплярам
или по выручке, «сезон» — календарный или квартал. Ответ на неверное прочтение выглядит
правдоподобно, и владелец не узнает, что посчитано не то.

## Решение
- При неоднозначности система **всегда** возвращает уточнение и не выполняет SQL.
- Обязательные поводы для уточнения — список «Термины, требующие уточнения» в `docs/sql-rules.md`;
  LLM может запросить уточнение и сверх списка.
- Уточнение — структурированный список вариантов, не свободный текст.
- Сервис не хранит состояние: клиент повторно присылает исходный вопрос вместе с выбранными
  вариантами (`{question, clarifications}`).
- Дополнительные вопросы к предыдущему ответу («а теперь по городам») в v1 не поддерживаются.

## Последствия
- Ответ API — одно из двух: уточнение или результат; клиенту нужно уметь показать варианты.
- Вопрос с выбранными вариантами однозначен, поэтому его можно положить в тестовый набор
  вместе с эталонным SQL. Отдельный класс тестов — «здесь модель должна переспросить».
- Не нужно хранилище сессий и служебные таблицы рядом со схемой магазина.
- Чтобы добавить дополнительные вопросы, понадобятся сессии на сервере, а это пересмотр ADR.
