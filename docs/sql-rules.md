# Правила предметной области для SQL

Единственный источник правды о том, как правильно считать данные этого магазина.
Отсюда читают: ревьюер SQL (`.claude/agents/sql-reviewer.md`), промпт LLM в продукте
и тестовый набор. Меняешь бизнес-логику — меняешь здесь, а не в трёх местах.

Структура таблиц — в `db/bookstore_schema.sql`.

## Смысл колонок, которые легко перепутать

| Колонка | Что значит | Когда использовать |
|---|---|---|
| `books.price` | текущая цена в каталоге | «сколько сейчас стоит книга» |
| `order_item.unit_price` | цена за 1 шт., зафиксированная в момент заказа | любые расчёты выручки и среднего чека |
| `promocodes.discount_sum` | текущая скидка промокода, ₸ | «какая скидка у промокода сейчас» |
| `orders.discount_per_order` | скидка на **весь заказ**, зафиксированная в момент заказа, ₸ | вычитать из выручки **один раз на заказ**, не на позицию |
| `orders.created_at` | когда клиент оформил заказ | вопросы про оформление заказов |
| `payments.created_at` | начало попытки оплаты | почти никогда для выручки |
| `payments.paid_at` | момент, когда деньги пришли (есть только у `succeeded`) | период выручки |
| `refunds.refunded_at` | момент возврата | период, в котором уменьшается выручка |

## Статусы

- `orders.status`: `pending` (оформлен), `confirmed` (магазин принял заказ в работу), `cancelled` (отменён).
- `payments.status`: `pending` (попытка идёт), `succeeded` (деньги пришли), `failed` (попытка не прошла).
- У одного заказа может быть несколько платежей (например, `failed`, затем `succeeded`),
  но не больше одного `succeeded`.
- Возвратов в статусах нет: возврат — это строка в `refunds`, привязанная к позиции заказа.
- Платёж `succeeded` бывает только у заказа `confirmed`: успешная оплата делает заказ
  принятым, и после неё статус не меняется. Любой возврат — даже всех книг — записывается
  только в `refunds`. Поэтому выручка закрытого месяца известна в момент `paid_at` и потом
  не меняется.
- `cancelled` возможен только до оплаты: у отменённого заказа нет платежа `succeeded`.
- Обратное неверно: `confirmed` без платежа `succeeded` — заказ принят, но деньги не пришли
  (оплата идёт или не прошла). В выручку он не входит, поэтому одного фильтра по статусу мало.
- Возврат возможен только по оплаченному заказу `confirmed`. Поэтому «все возвраты за период»
  и «возвраты по заказам, входящим в выручку» — одно и то же множество.

## Выручка

Выручка за период =
сумма `order_item.unit_price × order_item.quantity`
по заказам, где `orders.status = 'confirmed'` и есть платёж `succeeded` с `paid_at` в периоде,
минус `orders.discount_per_order` (ровно один раз на заказ),
минус возвраты `refunds.quantity × order_item.unit_price`, у которых `refunded_at` в этом же периоде.

- Возврат уменьшает выручку того периода, **в котором произошёл**, а не периода продажи:
  отчёт за закрытый месяц не меняется задним числом.
- «Выручка», «продажи», «доход», «сколько заработали» — по умолчанию это выручка по правилу выше.

## Количество проданного

- Продано экземпляров = сумма `order_item.quantity` по тем же заказам, что и для выручки,
  минус `refunds.quantity` возвратов этого периода.
- «Количество заказов» — число различных `orders.id`, а не число позиций.
- Средний чек = выручка ÷ количество заказов (без учёта возвратов, если не сказано иначе).

## Авторы и жанры

- У книги может быть несколько авторов (`book_author`). Выручка «по авторам» засчитывает книгу
  **каждому** её автору полностью, поэтому сумма по всем авторам может быть больше общей выручки.
  Это ожидаемо; если вопрос о доле автора в общей выручке — нужно уточнить у пользователя.
- Так же считаются экземпляры «по авторам»: 2 проданных экземпляра книги двух авторов —
  по 2 у каждого.
- У книги ровно один жанр (`books.genre_id`), поэтому сумма выручки по жанрам равна общей выручке.

## Даты и часовой пояс

- Все моменты событий — `timestamptz`. Магазин работает по времени `Asia/Almaty` (UTC+5);
  «март» означает март по этому времени.
- Сессии базы работают в часовом поясе `Asia/Almaty` (настройка базы), поэтому литерал без пояса
  читается по Алматы: `paid_at < '2026-04-01'` — до полуночи 1 апреля по Алматы.
  `date_trunc('month', колонка)` тоже даёт месяц по Алматы.
- Период задаётся как `колонка >= начало AND колонка < начало_следующего`.
  `<=` с полуночью следующего периода и `BETWEEN` с датой — ошибки.
- Колонку в `WHERE` не оборачивать в `::DATE` и функции — иначе не работает индекс.

## Клиенты

- «Новый клиент в периоде» — `users.registered_at` в периоде.
- «Повторный покупатель» — клиент с двумя и более заказами, которые входят в выручку
  (`confirmed` + `succeeded`).
- Город — `users.city`; у части клиентов он может быть не указан (`NULL`).

## Промокоды

- Заказ без промокода: `orders.promocode_id IS NULL`, `orders.discount_per_order = 0`.
- «Сколько отдали скидками» — сумма `orders.discount_per_order` по заказам, входящим в выручку.
